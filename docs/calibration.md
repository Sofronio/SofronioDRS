# 校准与容器命令（BLE / USB）

用户提供秤上砝码/物体的**实际重量**，固件根据当前读数自动换算出新的校准系数并写入 EEPROM。
BLE 和 USB 两条命令共用同一套校准流程。

另外提供"记录容器重量"命令：把秤上当前重量记录为容器重量并写入 EEPROM。

- BLE 命令字:`0x30` 实际重量校准、`0x31` 记录容器(写特征 `36F5`,自定义命令区,避开标准协议的 `0x1C` 蜂鸣器 / `0x1D` 采样设置)
- USB 命令:`calw <实际重量g>` 校准、`ctr` 记录容器
- 支持固件:v6.1.3 及之后(含本功能)

---

## 1. 校准原理

电子秤的读数换算:

```
weight(g) = (raw - tareOffset) × (1 / calFactor)
```

其中 `calFactor` 即 EEPROM 地址 `i_addr_calibration_value`(地址 0,4 字节 float)保存的校准系数。

用户提供实际重量 `known_mass` 后:

```
new_calFactor = old_calFactor × current_weight / known_mass
```

计算完成后立即调用 `setCalFactor()` 生效,并把新系数写入 EEPROM。

为了保证读数可靠,固件在校准时会:

1. 临时切换到 **16 个采样**取平均(与菜单里的"智能校准"一致),调用 `refreshDataSet()` 重新填满数据集;
2. 再收集约 **250ms** 的数据做稳定性检查;
3. 读数绝对值 **< 5g** 视为秤上没有砝码,拒绝校准;
4. 两次读数差 **> 0.5g** 视为不稳定,拒绝校准;
5. 校准成功后清零旧的漂移补偿和跟踪偏移(`f_driftCompensation`、`resetTracking()`、`resetStableOutput()`)。

## 2. BLE 命令

### 2.1 服务与特征

| 项目 | UUID |
| --- | --- |
| 服务 Service | `FFF0` |
| 写特征 Write | `36F5` |
| 读/通知特征 Read/Notify | `FFF4` |

### 2.2 写命令帧(手机/上位机 → 秤,共 7 字节)

```
03 30 <float32 实际重量(g), 小端> <XOR>
```

| 字节 | 说明 |
| --- | --- |
| `[0]` | 型号字节,固定 `0x03` |
| `[1]` | 命令字节,固定 `0x30`(按实际重量校准) |
| `[2..5]` | 实际重量,IEEE-754 float32,**小端序**,单位 g(支持小数) |
| `[6]` | 校验:`[0]..[5]` 逐字节异或 |

示例:

| 实际重量 | float32 小端字节 | 完整帧 |
| --- | --- | --- |
| 500 g | `00 00 FA 43` | `03 30 00 00 FA 43 8A` |
| 1000 g | `00 00 7A 44` | `03 30 00 00 7A 44 0D` |
| 200 g | `00 00 48 43` | `03 30 00 00 48 43 38` |
| 57 g | `00 00 64 42` | `03 30 00 00 64 42 15` |

### 2.3 应答帧(秤 → 上位机,通过 FFF4 notify,共 12 字节)

上位机需要先订阅 `FFF4` 的通知。

```
03 B0 <status> <float32 实测重量(g), 小端> <float32 新校准系数, 小端> <XOR>
```

| 字节 | 说明 |
| --- | --- |
| `[0]` | 型号字节,固定 `0x03` |
| `[1]` | 应答字节,固定 `0xB0` |
| `[2]` | 状态码,见下表 |
| `[3..6]` | 校准时秤的实测重量(g),float32 小端 |
| `[7..10]` | 计算出的新校准系数,float32 小端 |
| `[11]` | 校验:`[0]..[10]` 逐字节异或 |

状态码:

| status | 含义 |
| --- | --- |
| `0` | 校准成功,已写入 EEPROM |
| `1` | 参数无效(帧长不足、校验失败、重量 ≤ 0 或非数字) |
| `2` | 秤上检测不到砝码(读数 < 5g) |
| `3` | 读数不稳定(两次读数差 > 0.5g),未写入 |
| `4` | 计算出的校准系数无效(非正数/NaN),未写入 |
| `5` | EEPROM 写入失败(运行值已更新,但未持久化) |

### 2.4 典型流程

1. 连接 BLE,订阅 `FFF4` 通知;
2. 空载稳定后(如需去皮,先发 `03 0F 00 00 00 00 0C`);
3. 放上已知砝码(建议 ≥ 50g,推荐 500g / 1000g);
4. 等读数稳定,发送 `03 30 ...` 校准帧;
5. 收到 `0xB0` 应答,检查 `status == 0`;
6. 秤的显示值应与砝码实际重量一致,断电重启后校准值仍然有效。

## 3. USB 串口命令

串口波特率 `115200`,命令以换行结尾(需开启换行符)。

### 3.1 校准

```
calw <实际重量g>
```

- 支持小数,如 `calw 500`、`calw 500.5`;
- 大小写敏感,命令与数字之间用空格分隔(也兼容 `calw500`)。

### 3.2 查看当前读数 / 用法

```
calw
```

不带参数时会打印用法和当前读数(方便确认重量):

```
Usage: calw <actual weight in grams>, e.g. "calw 500"
Current reading: 499.87g
```

### 3.3 示例输出

```
calw 500
Calibration OK: measured=468.30g	target=500.00g	newCalFactor=12345.67
Weight calibration result: 0	measured: 468.30g	new cal factor: 12345.67
```

失败时(例如没有砝码):

```
Calibration failed: no weight detected
Weight calibration result: 2	measured: 0.12g	new cal factor: 1000.00
```

### 3.4 Python 示例(USB)

```python
import serial, time

ser = serial.Serial("/dev/cu.wchusbserial130", 115200, timeout=1)
ser.write(b"calw 500\n")
time.sleep(0.5)
print(ser.read(512).decode(errors="replace"))
ser.close()
```

### 3.5 Python 示例(BLE,bleak)

```python
import asyncio
import struct
from bleak import BleakClient

WRITE_UUID = "000036f5-0000-1000-8000-00805f9b34fb"
NOTIFY_UUID = "0000fff4-0000-1000-8000-00805f9b34fb"

def xor(data: bytes) -> int:
    value = 0
    for b in data:
        value ^= b
    return value

def make_cal_frame(weight_g: float) -> bytes:
    body = bytes([0x03, 0x30]) + struct.pack("<f", weight_g)
    return body + bytes([xor(body)])

async def main():
    async with BleakClient("Decent Scale") as client:
        await client.start_notify(NOTIFY_UUID,
                                  lambda _, data: print("notify:", data.hex(" ")))
        await client.write_gatt_char(WRITE_UUID, make_cal_frame(500.0), response=True)
        await asyncio.sleep(5)

asyncio.run(main())
```

> 备注:ESP32 BLE 默认 MTU 为 23,12 字节应答帧无需协商更大 MTU。

## 4. 校准步骤建议

1. 开机,让秤预热/稳定(空载时显示 0);
2. 建议先清零/去皮,保证零点准确;
3. 把砝码放在秤盘**中心**,避免偏载;
4. 等显示读数稳定 2~3 秒;
5. 发送校准命令,确认返回成功;
6. 用第二个已知重量复核(如用 500g 校准,再用 200g 验证)。

## 5. 容器重量命令（记录当前重量）

与菜单“自动扣除设置 → 设置容器重量”功能一致：把秤上**当前重量**记录为容器重量，写入 EEPROM
(`i_addr_container`)。记录后，当秤上出现该容器时显示值会自动扣除容器重量。

### 5.1 USB 命令

| 命令 | 说明 |
| --- | --- |
| `ctr` | 把当前重量记录为容器重量（新命令） |
| `ct <g>` | 直接把容器重量设为指定值（原有命令，不做“当前读数”采样） |
| `ct 0` | 清除容器重量 |

示例:

```
ctr
Container recorded: 18.52g
Container record result: 0	measured: 18.52g	container: 18.52g
```

处理逻辑与校准命令相同：16 采样平均 + 约 250ms 稳定性检查，读数 **< 1g** 视为没有容器，
两次读数差 **> 0.5g** 视为不稳定（均拒绝写入）。

### 5.2 BLE 命令

无负载，共 3 字节（写特征 `36F5`）:

```
03 31 32
```

| 字节 | 说明 |
| --- | --- |
| `[0]` | 型号字节,固定 `0x03` |
| `[1]` | 命令字节,固定 `0x31`(记录容器) |
| `[2]` | 校验:`0x03 ^ 0x31 = 0x32` |

应答帧（通过 `FFF4` notify，共 12 字节）:

```
03 B1 <status> <float32 实测重量(g), 小端> <float32 容器重量(g), 小端> <XOR>
```

| 字节 | 说明 |
| --- | --- |
| `[0]` | `0x03` |
| `[1]` | `0xB1` |
| `[2]` | 状态码,见下表 |
| `[3..6]` | 记录时的实测重量(g),float32 小端 |
| `[7..10]` | 保存后的容器重量(g),float32 小端 |
| `[11]` | 校验:`[0]..[10]` 逐字节异或 |

状态码:

| status | 含义 |
| --- | --- |
| `0` | 记录成功,已写入 EEPROM |
| `1` | 命令帧无效(长度不足或校验失败) |
| `2` | 秤上检测不到容器(读数 < 1g) |
| `3` | 读数不稳定(两次读数差 > 0.5g),未写入 |
| `4` | EEPROM 写入失败 |

### 5.3 使用步骤

1. 空载时先清零(必要时发 tare / 按清零键);
2. 把容器(手柄/杯子等)放在秤盘上;
3. 等读数稳定 1~2 秒;
4. 发送 `ctr`(USB)或 `03 31 32`(BLE);
5. 收到成功应答后,容器在秤上时显示会自动扣除容器重量。

## 6. 注意事项

- **阻塞时间**:校准过程约 1~3 秒(16 采样平均 + 250ms 稳定性检查),期间固件不刷新显示、BLE 重量通知暂停,属于正常现象。
- **稳定性阈值**:读数 < 5g 或两次读数差 > 0.5g 会被拒绝,请待秤稳定后重试。
- **EEPROM 共用**:新系数写入与菜单校准相同的地址(地址 0),两种校准方式互相覆盖。
- **旧命令兼容**:`cv <系数值>` 仍可直接写入指定校准系数(不做换算),`cal` 仍可启动屏幕交互式校准。
- **BLE 帧校验**:新增命令沿用 Decent Scale 协议的型号字节 `0x03` 与异或校验;**应答帧的校验是所有前序字节异或**(包括 `0x03` 与 `0xB0`/`0xB1`),与旧版 7 字节帧的算法一致:即 `XOR(b[0..len-2])`。
- **命令号选择**:自定义命令使用 `0x30`/`0x31`/应答 `0xB0`/`0xB1`,不占用标准 Decent 协议已定义的 `0x1C`(蜂鸣器)、`0x1D`(采样设置)、`0x1E`(菜单/关于/Debug)、`0x1F`(重启)等字节,避免与标准 APP 互相干扰。

## 7. 标准 Decent 命令（已移植,中文界面）

以下命令与 openscale / de1app 的标准 Decent Scale 协议一致,无需校验字节。

### 7.1 蜂鸣器 `0x1C`

```
03 1C <mode>
```

| mode | 功能 |
| --- | --- |
| `00` | 关闭蜂鸣器（运行时,不写 EEPROM） |
| `01` | 开启蜂鸣器 |
| `02` | 鸣叫一声 |

### 7.2 采样设置 `0x1D`

```
03 1D <samples>
```

| samples | 采样数 |
| --- | --- |
| `00` | 1 |
| `01` | 2 |
| `03` | 4 |

其他值忽略。采样数为运行时设置,不写 EEPROM。

### 7.3 菜单 / 设备信息 / 调试 显隐 `0x1E`

```
03 1E <group> <show>
```

| group | 界面 | show=00 | show=01 |
| --- | --- | --- | --- |
| `00` | 设置菜单 | 隐藏 | 显示（中文菜单） |
| `01` | 设备信息 | 隐藏 | 显示（中文界面） |
| `02` | 调试信息 | 隐藏 | 显示（中文界面） |

- 设备信息界面显示：`设备信息` / `固件:x.x.x` / `PCB:x.x` / `序列号:xxx`；
- 调试信息界面显示：固件版本、GPIO、陀螺、充电状态、蓝牙状态、电压、电量、重量、计时；
- 设备信息界面下按任意键关闭；调试界面可通过再次发送 `03 1E 02 00` 或长按去皮键退出。

### 7.4 重启 `0x1F`

```
03 1F
```

立即软重启（ESP32 `ESP.restart()`），屏幕显示“重启中”。

### 7.5 校准 `0x1A`

```
03 1A <mode>
```

| mode | 功能 |
| --- | --- |
| `00` | 手动校准：设备屏幕提示选择砝码（设置键切换、去皮键确认） |
| `01` | 智能校准：与 openscale 一致，默认禁用，屏幕提示“智能校准未启用” |

校准流程见第 8 节。

## 8. 菜单校准（openscale 逻辑）

从菜单 `称重 → 开始校准` 或 BLE `0x1A 00` 启动，流程与 openscale 一致：

1. **选择砝码**：设置键循环选择 `50/100/200/500/1000g`，去皮键确认（选择“退出”则放弃）。
2. **0g 捕获**：提示移开砝码，3 秒倒计时后采集 16 个采样；
   - ADC 超时/采样不足/超量程 → 校准失败；
   - 连续 3 次读数、保持 ≥1 秒、波动在允许范围内才算稳定；
   - 完成后执行 `tare()` 清零。
3. **负载捕获**：提示放上所选砝码，3 秒倒计时后同样方式采集稳定读数。
4. **系数计算与校验**（`calibration_validation.h`）：
   - 候选系数 = `(负载原始值 - 零点原始值) / 实际重量`；
   - 检查重量有效、原始差值、系数范围（1 ~ 1,000,000）、**系数符号与原始差值方向一致**（允许合法负系数）；
   - 应用候选系数后复核显示重量，误差需 ≤ `max(0.5g, 实际重量 × 3%)`。
5. **保存**：校验通过后写入 EEPROM 地址 0，并清零漂移补偿/跟踪偏移；失败则恢复旧系数，不写 EEPROM。
6. **失败原因**显示在屏幕上（中/英），例如：零点不稳、加载不稳、重量变化太小、系数符号错误、复核失败、智能校准未启用；串口输出完整诊断（原始值、差值、波动、候选/旧系数、复核重量）。

> 与旧版菜单校准相比：新增稳定性/范围/符号校验和校准后复核，失败不会破坏原校准值；智能校准默认禁用（与 openscale 相同）。

- **字节序**:BLE 帧中的 float32 均为**小端序**(ESP32 原生字节序,可直接 `memcpy`)。
- **数据安全**:若 EEPROM 提交失败,本次校准不会持久化(状态码 `5`),重新上电后会恢复旧系数。
